## 2. 版本说明草稿

以下为 0.1.0 开发范围，最终发行前逐项与验收证据对照；未通过的功能不得写成已经可用：

- 原创程序绘制的三种瓶型、三种基质层、两种苔藓、两种小型观叶植物和石头/木头装饰。
- 水分、瓶盖、光照、温度影响游戏化生态近似；不是科学养护模型。
- 默认运行 24×；相对倍速 1/2/5/10 对应现实时间 24/48/120/240×；离线按现实 1×；暂停不推进。
- 本地存档、JSON 导出/导入，透明挂件、编辑窗口与托盘恢复入口。
- 无云 AI、账号、遥测、远程内容与日常网络依赖。

已知限制：Setup 的 NSIS 嵌入插件许可未核验，安装器仅内部候选不可分发；安装生命周期、物理锁屏/多屏/DPI、真正 OS 点击穿透和原生拖动等未完成实机全测。macOS 尚未真机验证；Windows 应用 `NotSigned`，可信代码签名及 macOS 公证尚未配置；自动更新、云同步和数据库迁移系统不在首版已交付范围。更丰富植物、蘑菇、主题及瓶型为后续扩展。发布负责人需增加真实已知问题，不使用“全部测试通过”等无证据表述。

## 3. 本地构建与 CI

在干净的产品源码副本中执行，不覆盖真实存档或用户正在修改的共享源码：

```sh
npm ci
npm run check
npm start
```

Electron 44.4.1 的 npm 包没有下载运行时的 `postinstall`，`npm ci` 只安装依赖包，`npm run check` 只执行测试与编译，不需要 Electron 二进制。`prestart`、`presmoke`、`prepack`、`predist:win`、`predist:mac` 自动运行 `setup:electron`，调用官方 `node node_modules/electron/install.js` 并校验下载 checksum。首次/缺少有效缓存或安装时须联网；已安装的有效版本会复用。缺失运行时排障可手动执行：

```sh
npm run setup:electron
```

不要跳过 checksum 或关闭系统安全防护。完整 Windows ZIP 已包含运行时，普通用户不需要 Node 或此准备命令。首轮干净源码已在 `npm ci`/97 项检查后成功安装官方运行时，随后源码真实冒烟 15/15 通过、无页面错误。

Windows 产物：

```sh
npm run dist:win
```

Mac 上的产物：

```sh
npm run dist:mac
```

结果位于 `release/`；脚本使用 `--publish never`。`npm run pack` 可供解包检查，不能代替安装器测试。当前 Windows ZIP 和 Setup 均已构建，但 Setup 仅内部候选，插件许可未解除前不能分发。`npm run smoke` 使用临时测试存档启动真实 Electron；2026-09-18 开发版和 Windows 打包应用各 15 项通过、无页面错误，最终验证脚本 8 项通过。工作台截图已完成视觉检查，使用自然风格原创程序绘制，不宣称照片级外观。脚本/窗口属性验证不替代真正 OS 点击穿透、原生拖动、物理锁屏、多屏/DPI 或人工故障验收。

工作流假定此产品已经被整理为**独立仓库根目录**；当前嵌套在 Foundry 的 `.github/` 配置不会成为 Foundry 根仓库工作流。

- `ci.yml`：push、pull request 或手动运行；Windows/macOS 各执行 `npm ci`、`npm run check`，只读仓库权限，不使用生产秘密，不用 `pull_request_target`。
- `release-build.yml`：仅 `workflow_dispatch`；在 Windows/macOS 原生 runner 分别构建安装包、生成 SHA-256 与构建信息，仅上传明确列出的最终产物到短期 Actions artifacts。不创建 tag、公开 Release 或商店提交。
- 手动工作流禁用签名证书自动发现，不注入签名/公证或生产秘密。macOS runner 构建成功不是完整真机兼容性验收，也不表示公证完成。
- Actions artifacts 的可见性由仓库和 GitHub 访问规则决定，**不是私人存档保险箱**；只上传审阅过的产物，不能上传整个工作区。当前不触发任何远程运行。

锁文件固定依赖解析，runner、系统工具、下载的构建工具与时间戳仍可能影响产物；不要宣称二进制可重复到逐字节一致。

普通运行不要求应用环境变量、API key、账号或服务连接。无需 `.env`，也没有生产环境变量清单或云数据库凭据。

开发安装可能受本机 npm 配置、代理和 Electron 下载配置影响；若排障需要它们，记录名称与非敏感行为，不复制 token、代理密码或私人 registry 凭据到源码、日志或 artifacts。

工作流使用 `CI=true` 与 `CSC_IDENTITY_AUTO_DISCOVERY=false`；GitHub 自带的 Actions artifact 凭据只用于本次构建结果传输，不是应用凭据。没有签名证书、`CSC_LINK`、`CSC_KEY_PASSWORD`、Apple 凭据、生产 secret 或发布 token 的配置。未来签名/公证必须另行设计最小权限渠道并获批准，严禁把证书或私钥提交到仓库。

日常应用运行离线；依赖安装、Electron/安装器工具下载、GitHub Actions 和未来 Apple 公证会访问网络，不能宣传“构建及发行全过程完全无网络”。

## 5. 本地数据、备份与升级

首版使用 schemaVersion `1` 的本地 JSON 状态，不引入云数据库，因此没有 SQL 数据库迁移、托管备份或服务器切换步骤。任何存档格式变化必须设计版本化迁移及失败恢复，并用样例数据测试；首版不是现成的通用迁移框架。

当前主进程实现：数据位于 Electron `app.getPath('userData')`，应用名为 `Mosslight`。典型目录为 Windows `%APPDATA%\Mosslight`、macOS `~/Library/Application Support/Mosslight`，实际目录受系统配置影响。主存档 `terrarium.json`、上一份有效备份 `terrarium.backup.json`；挂件位置为 `window.json`。开发版及 Windows 打包应用保存重开、8 小时离线 1× 已通过真实运行验证，macOS 目录与行为尚未真机验证。

存档带 SHA-256 内容校验（不是加密或来源认证），JSON 最大 256 KiB。写入使用同目录临时文件、同步和重命名；失败可能留下可恢复临时文件。无法读取的主存档或备份会尝试保留为 `terrarium.recovered-时间-随机值.json`，并尝试读取有效备份。无法保留原损坏文件时，禁止后续覆盖保存与导入，但允许查看有效备份及导出。合法导入经用户确认后，原瓶子先保留为 `before-import-时间.json`，外部电脑偏好不导入、外部存档不补算离线时间；导入时间锚点归一到接收机，界面使用单调快照序号而非墙钟判定新旧。

损坏存档、保留失败、超限文件、合法跨电脑时钟差、回拨后的导入及界面顺序已通过自动逻辑回归和独立 QA 修复复核。它们不构成真实权限/满盘/断电或原生文件对话框已通过的证明。

发布负责人仍需确认发行版最终目录、真实磁盘原子性/失败保护与恢复结果，以及离线结算与时间边界，不写未经确认的离线结算上限。不得用自动逻辑回归宣传已完成所有数据故障验收。

**保护状态的处理步骤：先导出当前生态瓶到可写位置，修复磁盘空间或权限问题，保留原损坏文件，再重启应用。** 当前会话的保护不会因导出成功或磁盘重新可写而自动解除，仍会禁止保存/导入；若原因是超限或其他异常文件，先确认安全恢复方案，不直接删除、覆盖原数据。

更新或测试前：

1. 从应用导出 JSON 到用户自行选择的安全位置，确认文件可读；该文件不加密，可能含自定义名称与偏好。
2. 退出应用；必要时在确认准确目录后额外复制本机存档及备份。不要删除、重置或自动改写真实存档来“修复”测试。
3. 用全新测试账户/明确的测试存档运行候选版本；先验证正常重开、损坏主存档、合法导入、非法/过大导入和失败时保留状态。
4. 如需恢复，先再备份当前状态，通过已验证的导入方式恢复兼容 JSON；旧版本对新 schema 未必兼容，不能直接降级覆盖。

ZIP 免安装不表示数据随程序目录携带，也不承诺卸载时数据保留/删除行为；两者均需在最终安装器实测后说明。

## 7. 签名、公证与第三方合规

当前 Windows 配置为 `signExecutable: false`，未启用代码签名；重建应用已含 Mosslight 名称、0.1.0 版本资源及 `scripts/icon.mjs` 生成的原创图标。应用 EXE 实际 Authenticode 状态为 `NotSigned`；资源编辑和原创图标不是代码签名。SmartScreen 可能提示不受信任，不能承诺未来签名一定消除所有安全警告。校验和不能替代签名与可信来源。不要建议关闭系统安全防护。

macOS `hardenedRuntime` 配置不等于 Developer ID 签名或 Apple 公证。当前两者未配置，临时签名不等于可信发行签名；Gatekeeper 可能拦截。普通公开发行前需要获准的签名、公证及实测流程，不禁用 Gatekeeper、不删除隔离属性绕过检查。背景见 [Electron 官方签名与公证文档](https://www.electronjs.org/docs/latest/tutorial/code-signing)。

`THIRD_PARTY_NOTICES.md` 为本次候选的冻结输入，不在产物核验期间修改；新的运行时/许可结论另行记录，不以文档漂移掩盖风险。已审阅的完整 Windows ZIP 快照通过许可原文保留和隐私范围核验，实际不含 elevate、NSIS stub 或安装器插件，Electron 两处 LICENSE/Chromium notices 副本与上游原文匹配，没有被应用 MIT 文本覆盖。

应用没有 production npm 依赖；实际应用 bundle 引用原创代码、Node built-ins 与 Electron，开发构建工具的 npm 包不随 app.asar 分发。不能把所有 devDependencies 都误算成被再分发的运行依赖，也不能因此忽略 Electron 内含组件的各自许可。结论只绑定已审阅 ZIP 快照；补运行时准备脚本后的新归档须重新检查清单/摘要并重绑，不沿用旧校验和作为最终值。额外下载及任何实际分发组件仍按各自义务审查，Mac 不由 Windows 原文副本结论覆盖。
